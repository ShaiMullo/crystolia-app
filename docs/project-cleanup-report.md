# Crystolia — Repository Cleanup Report

> **Read-only audit.** Nothing was deleted, moved, or modified to produce this
> report. Every item is a *recommendation only*. Review with the team before any
> deletion. Generated 2026-06-22 during the ERP-integration preparation sprint.
>
> **Classification legend**
> - **SAFE TO DELETE** — regenerable or clearly junk; near-zero risk.
> - **LIKELY SAFE TO DELETE** — almost certainly unused; verify once.
> - **NEEDS REVIEW** — possibly used; a human must confirm before removal.
> - **KEEP** — in active use or intentionally present; do **not** delete.

## Scope & method

Audited `crystolia-app` (the git repo) across backend, frontend-admin,
frontend-client, landing, leads-api, docs, scripts, tools, deploy, helm,
terraform-cheap, and `.github`. Method: `git ls-files`, `git status`, `find`,
`grep` for usage/dead-code, and tracked-vs-on-disk comparison. Sibling
directories under `/Users/shaimullo/projects` (`crystolia-gitops`,
`crystolia-infra`, `design-system`, `oil-landing`) are **out of repo** and only
noted briefly at the end.

> Note: this report excludes the new ERP-integration files added during this
> sprint (they are intentional and tracked separately).

## Detailed findings

### 1. `data/mongo/` — local MongoDB data volume — **LIKELY SAFE TO DELETE (locally)**
- **What:** 202 MB of WiredTiger files (`*.wt`, `mongod.lock`) — a local Mongo
  instance's data dir.
- **Why safe:** Gitignored (`data/mongo/`), never tracked. It is local developer
  state, not source. Deleting it only wipes a local DB you can re-seed
  (`npm run seed`).
- **Risk:** Low — *only* if this machine holds data you haven't backed up. Not
  part of the repo.
- **Impact:** Frees 202 MB locally. No effect on git/CI/production.

### 2. Build artifacts — **SAFE TO DELETE**
- **What:** `frontend-admin/.next` (76 MB), `frontend-client/.next` (34 MB),
  `landing/.next` (12 MB), `landing/out` (17 MB), and `*.tsbuildinfo` files.
- **Why safe:** All gitignored and regenerated by `next build` / `tsc`.
- **Risk:** Low — next build just recreates them.
- **Impact:** Frees ~140 MB locally; speeds nothing but declutters.

### 3. `.DS_Store` — **SAFE TO DELETE**
- **What:** 5 macOS Finder metadata files on disk.
- **Why safe:** Gitignored, never tracked, pure OS noise.
- **Risk:** None.

### 4. Root `package.json` + `package-lock.json` + `node_modules/` — **NEEDS REVIEW**
- **What:** `crystolia-app/package.json` declares a single dep
  `@aws-sdk/client-sns` and ships a 50 KB `package-lock.json` and a populated
  root `node_modules/`. Every real app (backend, frontends, landing, leads-api)
  has its **own** `package.json`.
- **Evidence of disuse:** `grep` for `@aws-sdk`, `client-sns`, `SNSClient` across
  **all** `.ts/.tsx/.js` source (excluding `node_modules`/lockfiles) returns
  **nothing**. The dependency is not imported anywhere.
- **Why review (not auto-delete):** A root-level package may be an intentional
  monorepo placeholder, or `@aws-sdk/client-sns` may be reserved for a planned
  SNS notification path. Confirm with the author before removing.
- **Risk:** Medium — removing a root `package.json` can affect tooling that
  assumes a workspace root.
- **Impact:** If confirmed orphaned, delete all three → removes an unused AWS SDK
  install and a misleading "root dependency".

### 5. `frontend-client/.../SecretaryDashboard.tsx` — **NEEDS REVIEW (possible dead component)**
- **What:** A full dashboard component. `grep "SecretaryDashboard"` across the
  repo finds only its own definition/interface — **no importer**.
- **Why review:** It may be (a) genuinely orphaned after a refactor, or (b)
  dynamically selected by role and missed by static grep. It also contains a
  `// TODO: Save to backend`, suggesting unfinished work.
- **Risk:** Medium — deleting a component that's actually routed breaks a page.
- **Impact:** If confirmed unused, removal trims dead UI. Confirm there's no
  role-based dynamic render first.

### 6. `tools/local/*.command` (18 files) — **KEEP**
- **What:** macOS double-click ops wrappers (deploy, dns, mongo-uri, firewall,
  smoke-test, etc.).
- **Why keep:** Gitignored on purpose (`*.command`) and documented by the tracked
  `tools/local/README.md`. They are intentional local helpers — and may embed the
  operator's home IP (see security audit), so they should stay **out of git**, not
  be deleted.
- **Risk of deleting:** Low functional, but you'd lose convenience scripts.

### 7. `scripts/*.sh` (deploy/health/rollback/smoke/validate) — **KEEP**
- **What:** 6 tracked ops scripts used by CI/deploy flows.
- **Why keep:** Referenced by deployment docs/Makefile. (Side note: they carry
  unusual perms `-rwx--x--x` — owner-only read; harmless but odd, see security
  audit.)

### 8. `docker-compose.{yml,dev,local,demo}.yml` (4 files) — **KEEP / NEEDS REVIEW**
- **What:** Four compose variants (base/dev/local/demo).
- **Why mostly keep:** Each targets a distinct environment and is referenced by
  the Makefile/docs.
- **Review:** Confirm `docker-compose.dev.yml` (215 B, minimal) is still used; if
  superseded by `.local`, it's a **LIKELY SAFE TO DELETE** candidate. Verify
  against Makefile targets first.

### 9. Overlapping documentation trees — **NEEDS REVIEW**
- **What:** `docs/deployment/`, `docs/deployment-cheap/`, and `docs/infrastructure/`
  cover overlapping ground (env-vars, rollback, cost-estimates appear in multiple
  places). `docs/infrastructure` alone has 19 files including `STATUS.md`,
  `ROADMAP.md`, `plan-analysis.md`.
- **Why review:** Likely some are stale snapshots from earlier phases. Consolidate
  rather than blind-delete — they may be referenced.
- **Risk:** Low. **Impact:** Clarity; no code impact.

### 10. `docs/architecture/command-center.html` — **NEEDS REVIEW**
- **What:** A standalone HTML file inside docs.
- **Why review:** Could be a one-off visualization/experiment. Confirm it isn't
  linked from a README or served anywhere.
- **Risk:** Low.

### 11. `deploy/demo/.env.demo` — **NEEDS REVIEW (handled in security audit)**
- **What:** A concrete `.env.demo` file present on disk (untracked — gitignore
  `.env.*` keeps it out of git).
- **Why review:** Not a cleanup target per se, but if it holds real demo
  credentials it should be rotated/secret-managed. Flagged here, detailed in
  `docs/security-audit.md`.
- **Risk:** Medium (secrets). Do **not** delete without checking it isn't the only
  copy of needed demo config.

### 12. `TODO`s and `console.log` — **KEEP / NEEDS REVIEW**
- **What:** 2 genuine `// TODO` (SecretaryDashboard, CustomerDashboard — both
  "save/upload to backend"); 60 `console.log` in `backend/src`.
- **Why mostly keep:** Most backend `console.*` is the intentional `opsLogger`
  JSON-line transport, not stray debug. The 2 TODOs mark unfinished client
  features, not cruft.
- **Action:** Review the 2 TODOs as product backlog; spot-check `console.log`
  outside `opsLogger.ts` for stray debug.

### 13. Root & docs status reports — **KEEP**
- **What:** `DEPLOYMENT_CHECKLIST.md`, `VERIFICATION_CHECKLIST.md`,
  `docs/RECOVERY_PLAN.md`, `docs/SYSTEM_AUDIT.md`, `docs/REPO_STRUCTURE_REPORT.md`,
  `docs/USER_JOURNEY.md`, `docs/project_map.md`.
- **Why keep:** Operational/onboarding documentation. Possibly slightly dated but
  useful; not cleanup candidates.
